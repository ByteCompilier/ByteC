01 / OVERVIEW

Programs are sequences of instructions

ByteC uses explicit instruction lines. Operands can include register names, numeric values, or labels depending on the instruction. The syntax is intentionally compact and visible.

A FIRST PROGRAM
MOV a 40
ADD a 2
PR a

This example places a value in register a, adds two, and prints the result.

02 / MACHINE MODEL

Registers

The ByteC virtual machine uses five general-purpose registers: a, b, c, d, and e. The project describes these as 64-bit registers.

General purpose

Use registers to store intermediate values and results.

MOV a 10
MOV b 20
ADD a b
PR a

Condition state

The condition state is named ZS and is used by comparison and conditional jump instructions.

CMP a == b
JIT equal_label
03 / DATA MOVEMENT

MOV — assign a value

MOV writes a literal or another register value into a destination register.

MOV a 12
MOV b a
PR b
04 / ARITHMETIC

Modify register values

Arithmetic instructions operate on registers with immediate values or register operands as supported by the current implementation.

MOV a 30
ADD a 12
SUB a 2
MUL a 2
PR a

ADD / SUB

Add or subtract the operand from the target register.

MUL / DIV

Multiply or divide a register value using the given operand.

INC / DEC

Increment or decrement the selected register.

NEG

Change a register's sign by negating its value.

05 / CONDITIONS

CMP and the ZS condition state

CMP compares operands and updates the condition state. Conditional jumps can use that state to alter program flow. Supported comparison forms should be confirmed against the current interpreter version.

MOV a 5
MOV b 5
CMP a == b
JIT same
MOV c 0
JMP done
: same
MOV c 1
: done
PR c

Labels are written with a colon, one space, and the label name on a separate line, such as : same.

06 / CONTROL FLOW

Jump between labels

ByteC provides unconditional and conditional jump instructions. Labels mark destinations within the source program.

MOV a 0
: loop
INC a
CMP a == 3
JIF finish
JMP loop
: finish
PR a

JMP is unconditional. JIT and JIF are conditional forms—check the project reference for their exact condition behavior.

07 / FUNCTIONS

CALL, ARG, RET

ByteC includes function-call instructions. The current examples use CALL to reach a label, ARG to read function arguments, and RET to return a value.

MOV a 40
MOV b 2
CALL add a b
PR a
JMP finish
: add
ARG c 1
ARG d 2
ADD c d
RET c
: finish

Function argument and return conventions are still evolving; refer to the source and sample programs for the latest details.

08 / OUTPUT

PR — print values

Use PR to print the contents of a register.

MOV a 2026
PR a
09 / REUSE

INCLUDE — reuse source

The project supports source inclusion for reusable code and standard-library files. Check the repository's STD/ directory for the currently provided libraries and their exact interfaces.

INCLUDE math.bytec
ByteC is actively evolving. This documentation is a companion guide; the repository and its tests are the authoritative source for exact current behavior.
